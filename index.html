Cybersecurity Vulnerability Identification Lab

Web Application Security — Practical Exercise

Identify vulnerabilities, security weaknesses, impacts, and appropriate controls.

Instructions

Read each scenario carefully and answer the questions using standard cybersecurity terminology.

There is no automated answer checking in this lab. Enter your answers into the textboxes provided.

Take a screenshot of every answer and share them to the class group.

Note: Base your answers on the scenario provided. Explain your reasoning rather than providing only a vulnerability name.

Challenge 1 — Credentials

A web application has a login form. The developer stores usernames and passwords directly in the HTML/ JavaScript code. A student inspecting the page source can see: 

username = "admin"
password = "admin123"

Task:

  1. Identify the security vulnerability class.
  2. Explain why this approach is insecure.

Challenge 2 — Password Storage

A website stores users' passwords using plaintext in its database.

Task:

  1. Identify the security weakness using standard terminology or an appropriate OWASP category.
  2. Explain why the weakness violates core security principles and other security objectives if the database is compromised.
  3. State the appropriate secure alternative.

Challenge 3 — Password Reset

An online banking application allows unlimited password-reset attempts and has no mechanism to detect or restrict abuse.

Task:

  1. Identify the security/ design weakness.
  2. Identify the security principles that may be affected.
  3. Discuss the potential impact on availability, integrity, and confidentiality.
  4. Design a control set to mitigate the weakness.

Challenge 4 — SSRF

A web application allows users to provide a URL for the server to fetch, without restricting which internal or external addresses can be accessed.

Task:

  1. What is SSRF.
  2. Explain how the vulnerability could expose internal resources.
  3. Design a mitigation strategy that prevents unauthorized requests to internal or restricted destinations.

Challenge 5 — Login

An attacker repeatedly attempts to log into an administrator account, and the application records no failed-login events and generates no alerts.

Task:

  1. Identify the security weakness.
  2. Identify the necessary preventive, detective, and/or responsive controls.
